## Что должно заработать

На вкладке «Бриф» менеджер кладёт бриф: вставляет или надиктовывает текст в поле либо загружает файл `.md`, `.txt`, `.docx`. Файл разбирается в Markdown; текст и так Markdown. Голос это диктовка средствами устройства в то же поле: своё распознавание речи в срезе A не строится.

Каждое сохранение создаёт новую версию брифа, прошлая не переписывается. Версии видны списком: номер, дата, источник (текст или имя файла); выбранная версия открывается как Markdown. Пустой бриф не сохраняется: «положите бриф», версии нет. Файл другого типа отклоняется с понятным текстом, введённый текст при этом не теряется. Тот же текст подряд не создаёт вторую одинаковую версию. Бриф видят менеджер проекта и администратор; заказчика и команды в срезе A ещё нет.

Канон документа: Markdown в хранилище версий из таска 01. Word, PDF и другие форматы на выходе собираются при экспорте в срезе C; здесь только вход.

## Критерии приёмки

- [ ] Текст сохраняется версией Markdown; номера версий растут, прошлая версия не меняется
- [ ] `.md`, `.txt`, `.docx` превращаются в Markdown без новой зависимости; из `.docx` берутся заголовки и абзацы, не сырой XML
- [ ] Пустой текст и пустой файл не создают версию; текст ошибки говорит, что положить
- [ ] Файл не того типа отклонён с понятным текстом; размер ограничен как у остальных загрузок приложения
- [ ] Тот же текст подряд не создаёт вторую одинаковую версию
- [ ] Список версий: номер, дата, источник; выбранная версия показана как Markdown
- [ ] Чужой проект отдаёт отказ
- [ ] Тесты роутера на временной SQLite (текст, файл, пусто, не тот тип, повтор) и тест вкладки во фронте
