## 1. Ключ компании и подписка (п. 1)

### 1.1. Что сказано

Бриф: «работать целой команде на базе подписки одной учётной записи»; 2026-10-18: «для маленьких компаний это одна подписка, для средних и крупных ключи на каждый проект или подразделение». P02: «только API-ключ компании; открыто до юриста»; на нём 00 §6, 02 §6.1, ADR-03. Срез A берёт ключ пользователя или вход владельца по подписке.

### 1.2. Варианты и законность

Условия по документам Anthropic на дату проектирования; дословная проверка, применимость к российскому юрлицу и доступность поставщика из РФ (S03) за юристом P02. Оба пути строятся так, чтобы ответ юриста включал или выключал путь без смены схемы.

| Вариант | Что говорят условия | Вердикт |
|---|---|---|
| В1. Одна подписка Pro или Max на команду и агентов | Потребительские условия: учётная запись личная, вход и учётные данные другим не передаются. Документация Claude Agent SDK: без предварительного одобрения Anthropic сторонний продукт не предлагает вход claude.ai и лимиты подписки, нужен API-ключ | **Не строится до ответа юриста и письменного одобрения Anthropic.** Требование брифа не снимается: режим `shared_subscription` зарезервирован в `model_access.mode`, проверки 1.4 его отклоняют. Маленькая компания из одного человека уже работает «на одной подписке» путём В4 |
| В2. API-ключ компании (Claude Console) | Коммерческие условия, предназначен для продуктов и автоматизации | **Умолчание**, цепочка проект → подразделение → компания |
| В3. Ключ через Bedrock, Vertex, Foundry | Договор с облаком | Подвид В2: строка поставщика с другим адресом; облако в РФ к юристу |
| В4. Личная подписка каждого участника на его собственные действия | Своя учётная запись своим владельцем; ограничение Agent SDK для сторонних продуктов остаётся | **Строится выключенным** (М-02) |
| В5. Командный тариф (Team, Enterprise) с местами | Место выдаётся человеку | Сводится к В4: один договор и счёт компании, но не одна учётная запись |
| В6. Поставщик формата OpenAI или отечественный | Условия поставщика; вывоз данных (02 О1) | Раздел 2, только одношаговые классы |

Вывод для пользователя: «вся команда на одной учётной записи» у Anthropic законно невыполнимо; ближайшие формы: ключ компании с лимитами по проектам (В2) и личные места на одном договоре компании (В4, В5).

### 1.4. Где какой путь

Подписка применяется, только если сразу: режим компании `personal_subscription` или `mixed`; у актора активная привязка; актор вызывает действие сам и сейчас (не событие, не расписание); результат сначала видит он. Иначе ключ компании; нет ключа: вызов выключен (02 §6.1).

| Операция | Ключ компании | Личная подписка |
|---|---|---|
| «Спросить по проекту» участником команды; ИИ-правка в своей ветке; черновик задания по кнопке | да | да, подписка нажавшего |
| Ответ поиска заказчику | да | нет |
| Запуск агента по `assign`, включая агента разработки | да | да, подписка назначившего, если запуск стартует в течение 10 минут; иначе ключ компании или ожидание, по настройке |
| Ревью по `docmr.review_requested`, извлечение после `source.indexed`, сверка по событию | да | нет: триггер событие |
| Расписание (02 §8) | да | нет |
| Эмбеддинги, распознавание речи | вне строк (A17, A24) | вне строк |

Запреты: токен подставляет только прокси `routing` (02 §4.1), в джейл и окружение не попадает; вызов с токеном X при `on_behalf_of != X` отклоняется и пишется в `office_audit`; `member.removed` отзывает привязку. Ответ поставщика 429 переводит привязку в `rate_limited`; в режиме `mixed` повтор по ключу компании, иначе запуск `paused` с причиной `provider_down`.

### 1.5. Переключатель и API

Порядок: администратор системы задаёт `OFFICE_ALLOW_SUBSCRIPTION=1` после ответа юриста (без флага режим виден серым «недоступно до юридического решения»); админ компании выбирает режим, видит таблицу 1.4, подтверждает паролем; участник подключает свою подписку, `check` делает пробный вызов на 1 токен. Возврат в `company_key` не удаляет привязки; идущие запуски доживают на своём пути.

| Метод и путь | Вход → выход | Права | Ошибки |
|---|---|---|---|
| PUT `/admin/model-access` | `{mode}` | админ компании, повторный пароль | 409 `subscription_disabled` |
| POST, DELETE `/me/model-subscription` | `{token}` → привязка без значения | сотрудник-исполнитель; удаление ещё админ компании | 409 токен уже привязан, 422 проверка |
| GET `/usage?by=access_path` | расход по путям | админ компании, МП своего проекта | |

События: `model_access.switched` (`company_id`, `from`, `to`, `actor`) и `model_subscription.revoked` (`user_id`, `reason`); слушают `channels`, `insight`. Имя не `subscription.*`: подписки на объекты (`office_subscriptions`, 09 §2.4) это другая сущность (05 §6 С10).

## 2. Внешние поставщики (п. 2)

### 2.1. Адаптеры

Внутри `routing` за швом `ModelGateway` (00 §4.1), второй уровень: адаптер на формат.

| Адаптер | Формат и транспорт | Классы | Когда |
|---|---|---|---|
| `claude_code` | Anthropic; `ClaudeBridge`, SDK, `max_turns=1` для одношаговых, полный цикл для запусков (ADR-04) | все | Срез B |
| `anthropic_http` | Anthropic, `POST /v1/messages`, прямой HTTP | одношаговые | **Отложено до: решение О2 после замера P20** |
| `openai_http` | OpenAI Chat Completions, `POST /v1/chat/completions`, прямой HTTP | одношаговые | **Отложено до: О2 и ответ юриста О1**; контракт и таблицы в срезе B |

HTTP-клиент из уже установленных зависимостей (`aiohttp` идёт с `aiogram`); пакеты `anthropic` и `openai` не добавляются (решение среза A). Chat Completions выбран, потому что совместимые адреса сторонних и отечественных поставщиков повторяют его; Responses API можно добавить вторым видом формата без смены шва.

### 2.2. Контракт

| Операция | Вход → выход | Правило |
|---|---|---|
| `describe()` | → формат, инструменты, рассуждение, кэш подсказки, структурный ответ, потолок контекста | Уточняется по `GET /v1/models`, если поставщик его даёт |
| `check(provider, credential_ref)` | → `ok` или `auth`, `network`, `not_found`, `region` | Пробный вызов на 1 токен |
| `complete(ModelRequest)` | `system`, `messages`, `max_output`, `effort`, `response_schema?`, `request_key` → `text`, `structured?`, `usage {input, output, cache_read, cache_write}`, `stop {end, max_tokens, refusal, error}` | Ключ из ссылки, в журнал не попадает |
| `stream(ModelRequest)` | → дельты, затем ответ | «Спросить», ИИ-правка; дельты в `/api/office/ws` |

| Понятие | Anthropic | OpenAI |
|---|---|---|
| Конституция | `system` | сообщение `system` или `developer` |
| Усилие | `output_config.effort`: `low`...`max` | `reasoning_effort`: `low, medium, high`; `xhigh`, `max` → `high` |
| Структурный ответ | `output_config.format` | `response_format` вида `json_schema` |
| Кэш | `cache_control`, `cache_read_input_tokens` | автоматический, `cached_tokens` |
| Отказ | `stop_reason=refusal` | `finish_reason=content_filter` |

Для всех: подсказку собирает `knowledge`, `verify_quote` от поставщика не зависит; без структурного ответа поставщик не допускается к `extract` и `check`.

## 3. Автоматический выбор модели и усилия (п. 29)

### 3.1. Цены

`office_model_prices` (писатель `tenancy`): `provider_id`, `model`, `input_per_mtok`, `output_per_mtok`, `cache_read_per_mtok`, `cache_write_per_mtok`, `long_context_threshold?` с ценами сверх него, `batch_discount?`, `currency`, `valid_from`, `source`. Новая цена это новая строка: прошлый месяц считается по прежней.

Стартовый справочник Anthropic (справочник на 2026-10-06, доллары за миллион токенов; админ сверяет при установке):

| Модель | Идентификатор | Вход | Выход | Чтение кэша | Роль |
|---|---|---|---|---|---|
| Claude Haiku 5.5 | `claude-haiku-5-5` | 0,10 | 0,50 | по прайсу | «Быстрая» 02 §6.2; подсказка длиннее 100 тыс.: 0,50 и 2,50 |
| Claude Sonnet 5.5 | `claude-sonnet-5-5` | 2,00 | 10,00 | 0,20 | Средний кандидат для `doc_review`, `check` |
| Claude Opus 5.5 | `claude-opus-5-5` | 4,00 | 20,00 | 0,20 | «Сильная» 02 §6.2 |
| Claude Fable 5.1 | `claude-fable-5-1` | 10,00 | 50,00 | 0,25 | Только по решению админа |

Цены 02 §6.3 совпадают с Haiku 5.5 и Opus 5.5, расчёты 01 §7.8 и 02 §6.3 верны. Для формата OpenAI цены вносит админ; без цены строка не кандидат `auto`. Рассуждение у Opus 5.5 не отключается, умолчание усилия у Opus 5.5 и Haiku 5.5 `medium`, у Sonnet 5.5 `high`, поэтому строка всегда передаёт усилие явно; перечень `effort` расширяется до `low, medium, high, xhigh, max`.

### 3.2. Политика

Режим строки `fixed` (одна модель и усилие на класс) или `auto` (выбор среди `candidates`). Как в OpenRouter: единый вход, учёт, лимиты, автоматический выбор; иначе: только одобренные кандидаты и качество по решениям людей.

`routing.resolve(task_class, project, actor, hints) → {provider_id, model, effort, access_path, credential_ref, price_id, reason}`; `hints`: `input_tokens_est`, `needs_tools`, `needs_structured`, `difficulty` (0-1 от вызывающего: число пар сверки, очки задачи, длина диффа), `sticky_key` (запуск или сессия правки).

| Шаг | Правило |
|---|---|
| 1 | Ближайшая строка класса: проект → подразделение → компания |
| 2 | Отбросить: поставщик не `active`; формат не умеет нужное (2.3); `export_class` запрещён; путь незаконен (1.4); нет цены |
| 3 | Липкость: в `sticky_key` уже выбран кандидат, он же (кэш подсказки, единый стиль) |
| 4 | Нижняя граница качества (3.3) не ниже `quality_floor`; меньше 30 исходов допускается только умолчание строки |
| 5 | Ожидаемая цена = цена × (вход + средний выход класса) / вероятность успеха; берётся минимальная |

### 6.2. Что ищется и как

Задание `core` ночью, писатель `knowledge`:

1. Берутся ядра принятых версий и подтверждённые требования участвующих проектов (не фрагменты, не источники, не код).
2. KNN требования по секциям `office_vectors` других разрешённых проектов, до 50 проектов за проход.
3. Пары с близостью выше порога (умолчание 0,85 по `model_tag`) уходят в класс `check` с цитатами обеих сторон; ответ: `duplicate`, `contradiction`, `reuse`, `unrelated`.
4. Не `unrelated` пишется в `office_cross_links` со статусом `proposed`.
5. Предел расхода: отдельная доля `share_cross_project` лимита компании (умолчание 5%), сверх неё проход прерывается.

`office_cross_links` (писатель `knowledge`): `company_id`, `a_project_id`, `a_ref` (требование или узел), `b_project_id`, `b_ref`, `kind enum(duplicate, contradiction, reuse, related)`, `score`, `evidence json` (две цитаты по 05 §3.10), `status enum(proposed, confirmed, rejected)`, `decided_by`, `decided_at`.

### 6.3. Права

| Кто | Что видит и делает |
|---|---|
| Участник команды с доступом к **обоим** проектам | Связь на карточке требования; подтверждает или отклоняет МП, БА, СА любого из двух проектов |
| Участник с доступом к одному проекту | Ничего: ни связи, ни счётчика (права до ранжирования, 00 §2 принцип 5) |
| Руководитель офиса, наблюдатель «компания» | Метрика портфеля «межпроектные противоречия» числом по подразделениям, без текста |
| Заказчик | Никогда |
| `search`, `ask`, агенты | Межпроектное не подмешивается в выдачу; агент видит связь только как отдельный инструмент MCP `cross_links(requirement)` при доступе назначившего к обоим проектам |

Подтверждённое противоречие порождает в каждом проекте кандидата риска (`cycle`), не правку требований. События `cross_link.proposed`, `cross_link.decided` (`link_id`, `kind`, `projects[]`), слушатели `channels` (МП обоих проектов), `insight`. API: GET `/requirements/{key}/cross-links?project=`, POST `/cross-links/{id}/decision` `{confirm|reject, reason}`, PUT `/admin/cross-project`.

## 7. Интерфейс: редактор, граф, карта экранов

### 7.1. Редактор с комментариями к абзацам

Требования: Markdown как канон «один абзац на строку» (05 §3.2 п. 4); идентификаторы абзацев и линии с сервера; комментарии на абзац и диапазон; пошаговое принятие ИИ-правок; таблицы и списки построчно; чтение с выделением для заказчика; долгое нажатие на телефоне; React 18.

| Вариант | Оценка |
|---|---|
| **TipTap** (ProseMirror, ядро MIT) | Markdown через расширение и `prosemirror-markdown`; атрибуты узла `pid`, `lineage` переживают правку; комментарии своими декорациями по якорям сервера, платное расширение не нужно. Минус: нормализация таблиц своя |
| Lexical (MIT) | `@lexical/markdown`; свои узлы ради якорей; меньше готового для таблиц, частые ломающие изменения |
| BlockNote (MPL, часть пакетов платная или GPL) | Экспорт Markdown с потерями по документации: против канона |
| CodeMirror 6 (MIT) | Строка = абзац, пометки на полях; для заказчика и менеджера это исходник, не документ |

Выбор: **TipTap на ProseMirror.** Сервер остаётся источником правды: редактор отправляет Markdown, `knowledge` нормализует, режет и возвращает идентификаторы абзацев. Совместной правки в реальном времени (Yjs) нет: модель правки это ветка автора и MR (ADR-08). Сравнение версий рисуется своим компонентом по `knowledge.diff`, не редактором. CodeMirror остаётся вторым режимом «исходник Markdown» для аналитика.

### 7.2. Граф связей

Нужно: окрестность на два шага (01 §8), цепочка «бриф → ... → руководство» слева направо, пунктир у `future`, список для диктора. Сравнивались Cytoscape.js (MIT), React Flow (раскладка отдельно, избыточен для чтения), Sigma.js (WebGL на десятки тысяч узлов, не нужен), D3-force (всё своё). Выбор: **Cytoscape.js** с `cytoscape-fcose` (окрестность) и `cytoscape-dagre` (цепочка), ленивая загрузка на вкладке «Граф»; тот же ответ `graph` выводится списком «узел → ребро → узел».

## 8. Инфраструктура

### 8.1. ffmpeg

Нужен с среза D, не только для ролика: распознавание речи (A24) принимает аудио 16 кГц моно, запись поставщика видеосвязи приходит в mp4, webm или m4a, перевод делает ffmpeg.

| Где | Как |
|---|---|
| Установщик | `apt` пакеты `ffmpeg` и `fonts-noto-core` (кириллица в титрах); проверка `ffmpeg -version`, наличия фильтра `subtitles` (libass) и кодера libvpx-vp9; libx264 необязателен (только для MP4); без ffmpeg установка предупреждает и выключает ролик и локальное распознавание записей, остальное работает. Обновление ставит то же. Двоичные файлы из пакетов ОС, в архив релиза не входят (лицензии GPL на стороне дистрибутива) |
| Распознавание (D) | Процесс заданий: извлечь звук, привести к 16 кГц моно, распознать, в режиме «только текст» удалить медиа сразу (ADR-13, ADR-29) |
| Ролик (G) | Playwright в джейле пишет видео сценариев (webm, 1280×720) и журнал шагов со временем; процесс заданий через `MediaEncoder` (10 §1, §9.3): обрезка пауз, склейка, титульная и финальная карточки (страница рендерится Playwright в картинку), титры из шагов сценария и текста руководства по времени журнала; режимы титров: мягкие WebVTT (умолчание) или вшитые (`subtitles`); выход по умолчанию WebM (VP9, Opus), MP4 H.264 по настройке, если в сборке есть libx264 (В10-07); звук пустой; озвучка **отложена до: P01** |
| Ресурсы | `nice`, 2 потока, предел времени 3× длительности, отдельный bwrap без сети; одновременно один ролик на сервер (доп.) |

### 8.4. Шим на серверах компании и телеметрия на живом проде (Дополнение 2026-10-23, A41-A45, A43)

Модуль `ops` (17) ничего не ставит на сервер платформы, кроме второго файла базы и проб: `telemetry.db` в `<данные>/office/ops/` (SQLite WAL, писатель только `ops`, уровни 1 мин, 5 мин, час, сутки; в копию 00 §5 раз в сутки только свёртки часа и суток), `office_heartbeats` и реестр проб `core` (17 §5.2); `update.sh --check-ops` проверяет запись в второй файл, свободное место под 14 дней минутных рядов (около 200 МБ на 20 серверов) и регистрацию проб каждого модуля. Серверы компании получают шим `scripts/ops/office-ops-shim` (POSIX sh, `docker` CLI, без демонов и портов): платформа генерирует пару ed25519 и показывает команду подготовки, которую человек выполняет под `root` сам (пользователь `office-ops`, ключ с `restrict,command=`, по выбору группа `docker` с предупреждением о правах root и ссылкой на rootless Docker в `guide:admin`); «Проверить» даёт факты и отпечаток ключа хоста, админ сверяет его с консолью поставщика и подтверждает, до этого сбора нет (И-51). Обновление шима: версия в `facts`, новая версия ставится той же командой подготовки по кнопке «Обновить шим» с подтверждением. Режим `platform` (17 §2.5, срез G) требует на сервере `docker compose` v2; стек проекта лежит в `/srv/office/<pid>-<env>/`. Терминал (17 §4.2): отдельный ключ без `command=`, закреплённый `known_hosts` вместо `known_hosts=None` (тот же рецепт предлагается личному терминалу чата как долг кода), запись asciicast v2 в `BlobStore`. Нет возможности (сервер за NAT, нет SSH): сервер остаётся `unreachable` с пояснением, остальное работает; `push_agent` после выпуска (В17-15).
