# 20. Аудитор плана и факта, PowerPoint и MS Project, закрытый контур

Дата: 2026-10-25. Основание: слова пользователя 2026-10-25 по итогам разбора pm-ai.ru (A50, A51, A52). Кода здесь нет. Решения `05-sverka-superarhitektora.md` §3 обязательны.

## 0. Решения этого файла

| № | Решение | Почему |
|---|---|---|
| А-01 | «Аудитор отчётности» это новый профиль агента в каталоге (уточнение 21 spec). Он читает факт из платформы, считает расхождение с планом и готовит черновик статуса. Не публикует, не принимает, не меняет план. Показывает расхождение, а не сглаживает его | A50; правило «агент сам не публикует» |
| А-02 | Факт берётся только из событий платформы: статусы задач, принятые версии, слитые запросы на слияние кода, зелёные и красные сверки, закрытые находки. Слова людей в чате фактом не считаются, пока их не принял человек | Честный статус не должен зависеть от настроения отчёта |
| А-03 | План берётся в порядке: база плана (`plan`, срез F), иначе сроки задач и вех, иначе «плана нет». При «плана нет» аудитор пишет это строкой и расхождение не считает | Нельзя считать отклонение от плана, которого нет |
| А-04 | Статус содержит три слоя: цифры (готово, в работе, просрочено, заблокировано), расхождения (каждое со ссылкой на источник), «что в отчёте не подтверждено фактом». Заказчику статус уходит только после публикации менеджером | Доверие к статусу |
| А-05 | PowerPoint (`.pptx`) входит в канал вывода `ExportRenderer` и в канал ввода `ingest_file`. Правка готовой презентации меняет только тексты и таблицы выбранных слайдов, оформление и макет слайдов не трогаются. Результат это новый файл, исходный не перезаписывается | A51; принятая версия не переписывается |
| А-06 | MS Project: обмен планом через открытый XML-формат (MSPDI, `.xml`). Двоичный `.mpp` не поддерживается напрямую: его пользователь сохраняет как XML в самой программе. Импорт создаёт дерево работ как черновик на согласование, экспорт отдаёт принятую базу | A51; формат `.mpp` закрыт, надёжного чтения без самой программы не обещаем |
| А-07 | Закрытый контур это режим установки компании, в котором ни один байт данных проекта не уходит за пределы сервера компании. Включается флагом на компанию, проверяется самопроверкой (А-08) | A52 |
| А-08 | В закрытом контуре: модели распознавания речи и эмбеддинги только локальные (A17, A24 уже допускают); генерация текста только через локальную модель, подключённую адаптером шлюза `ModelGateway`; выключены облачные коннекторы (Google, Atlassian cloud, Notion, Figma, Asana, ClickUp, Trello, Linear), MCP-серверы с внешней сетью, расширения браузера из магазина, видеосвязь Телемост и Контур.Толк, внешняя почта, обновления из сети. Самопроверка перечисляет, что отключено и что ещё ходит наружу | Закрытый контур без проверки это обещание без доказательства |

## 1. Аудитор плана и факта (A50)

### 1.1 Что он делает

| Шаг | Вход | Выход |
|---|---|---|
| Собрать факт | События `cycle`, `delivery`, `plan` за период | Список изменений состояния |
| Сопоставить с планом | База плана или сроки задач и вех (А-03) | Таблица «план, факт, расхождение» по этапам, вехам и требованиям |
| Найти расхождения | Правила, без модели: просрочка, блокировка, требование без задачи, задача без сверки, «готово» без зелёной сверки | Список расхождений со ссылками |
| Найти неподтверждённое | Текст прошлого статуса и сообщения команды | Утверждения без фактов («почти готово» при красной сверке) |
| Написать черновик | Всё выше | Документ вида `status_report`, версия `draft`, цитаты на источники |

Арифметика и правила расхождений считаются кодом, не моделью. Модель пишет только текст и ищет неподтверждённые утверждения. Каждое утверждение статуса имеет ссылку; без ссылки оно не выводится.

### 1.2 Права и публикация

Профиль читает в правах назначившего. Результат виден команде. Заказчику документ открывается после «опубликовать» менеджером (история 18, P18). Отклонения самого аудитора не скрываются настройкой «показывать зелёным».

Дополнение 2026-10-26 (сверка 27, У27-09; И-73, И-87). «Права назначившего» у МП включают базу с деньгами (`bac`, резервы, факт затрат), а `status_report` видит вся команда. Поэтому аудитор работает в области аудитории вывода `internal` без класса `budget`: данные `plan` приходят проекцией без денег (как у `draft_artifact`, `21` §3.3), расхождения по срокам, объёму и сверкам считаются как прежде, отклонение по стоимости пишется только в вид класса `budget` (отдельный раздел для видящих `plan.budget/view`), а в общем статусе остаётся строкой «есть отклонение по стоимости, видно руководству» без сумм. С подсрезом G3 аудитор берёт факты через `insight.collect_facts` в той же области (`26` §1).

### 1.3 Связь с остальным

- Расхождения «требование без задачи» и «готово без сверки» берутся из матрицы следа (`cycle.trace_matrix`), как у стража цепочки.
- Освоенный объём и прогноз сдвига критического пути остаются отложенными (D06). Аудитор их не считает. Когда D06 вернётся, он подключит эти числа.
- Расписание: еженедельно или по команде. Лимит как у остальных профилей (`share_assistant`).

## 2. PowerPoint и MS Project (A51)

### 2.1 PowerPoint

| Операция | Правило |
|---|---|
| Вход `.pptx` | Через `knowledge.ingest_file`: текст слайдов, заметки докладчика, таблицы; изображения как вложения без распознавания в первом выпуске. Версия Markdown, слайды как разделы |
| Правка | Агент предлагает замены текста и значений таблиц по слайдам; человек принимает блоками; платформа применяет только к текстовым полям и ячейкам, форматирование сохраняется |
| Выход | Презентация собирается экспортом из шаблона компании: статус, итоги этапа, отчёт проекта. Шаблон загружает админ |
| Что не обещаем | Правку графиков, анимаций, макетов слайдов и встроенных объектов. Они остаются как есть |

Библиотеку чтения и записи `.pptx` выбирает исполнитель таска 86 по лицензии и сохранению оформления. Какие элементы сохраняются, проверяется на пяти реальных презентациях заказчиков (раздел 5).

### 2.2 MS Project

- Импорт MSPDI создаёт дерево работ (`office_wbs_items`) черновиком: задачи, вехи, сроки, связи «после», ресурсы как роли. Менеджер принимает как базу (график создаёт не платформа, а человек).
- Экспорт отдаёт принятую базу плана и текущие сроки в MSPDI.
- Конфликт: правки в двух системах не сливаются автоматически. Импорт всегда новая версия, сравнение показывает разницу.
- Диаграмма Ганта в самой платформе остаётся отложенной (D06). MS Project закрывает потребность на время, пока её нет.

Дополнение 2026-10-27 (проверка ИБ 29, УИБ29-27). Экспорт MSPDI со стоимостями и ставками только при `plan.budget/view`, иначе без денег; выгрузка в аудит. Импорт: ставки получают класс `budget`, имена ресурсов проходят `pseudonymize`.

## 3. Закрытый контур (A52)

### 3.1 Что обещает режим

Данные проекта (документы, письма, записи, расшифровки, граф) не покидают сервер компании. Все вызовы моделей идут на локальный сервер моделей.

### 3.2 Главное ограничение

Claude Code и Claude Agent SDK ходят в API Anthropic. Закрытый контур возможен только если генерацию текста выполняет другая, локальная модель через адаптер шлюза `ModelGateway` (срез B, адаптер формата OpenAI, сейчас выключен до юриста). Нужен локальный сервер моделей с совместимым интерфейсом. Сможет ли выбранная локальная модель выполнять роли платформы (извлечение требований с цитатами, сверка, код, агент разработки) на приемлемом качестве, не известно: это нужно измерить (раздел 5).

Классы работ, которые идут только через Claude Code (`code`, `browser_check`, `design`, spec 22), в закрытом контуре недоступны, пока не появится проверенная замена. Платформа показывает, какие функции выключены.

### 3.3 Состав режима

| Часть | В закрытом контуре |
|---|---|
| Генерация текста | Локальная модель через `ModelGateway`, ключ и адрес в `office_credentials` |
| Эмбеддинги, распознавание речи | Локальные (A17, A24) |
| Видеосвязь | Загрузка записи вручную; свой Телемост и Толк недоступны |
| Коннекторы A47 | Только установленные внутри контура (например, Jira Data Center, Confluence Data Center, Яндекс Трекер внутри), адрес в настройке. Облачные выключены |
| Библиотека MCP (A48) | Только серверы без внешней сети |
| Расширения браузера | Только из внутреннего каталога компании |
| Обновления | Вручную пакетом, без обращения к сети |
| Самопроверка | Экран «Закрытый контур»: список выключенного, список исходящих адресов за 24 часа, красная отметка при любом внешнем запросе |

Дополнение 2026-10-26 (сверка 27, У27-12, У27-13; И-88). Строки, которых не хватало таблице выше:

| Часть | В закрытом контуре |
|---|---|
| Уведомления (`25`) | Telegram и Макс выключены; почта только через SMTP внутри контура; уровень `link_only` без кода проекта |
| Ответы ассистента во внешних каналах (`13` §1.7) | Мессенджеры выключены; почта `link_only` |
| Внешний клиент MCP (Claude Code, Cursor) | Токен `mcp` получает только метаданные, без текста (`02` §7, дополнение 27) |
| Коллегиальный ресёрч и перепроверка (`25` §7, §8) | Только локальные модели; при одной локальной модели ресёрч недоступен |

### 3.4 Что остаётся нерешённым

См. раздел 5. Поставка оборудования и серверов моделей вне платформы (это услуга внедрения, не код).

Дополнение 2026-10-27 (проверка ИБ 29, УИБ29-56). По `28` Р28-01 контур всегда: флага «закрытый контур» и умолчания «выключен» больше нет, исходящий трафик закрыт, каждый выход это правило шлюза; одношаговые вызовы локально, многоходовые через `LocalLoopRunner` (Р28-05). Самопроверка §3.3 стала экраном «Контур» (`28` §7.1).
