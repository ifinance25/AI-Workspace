# 42. Пилот: сервер базы знаний ФАКТ в чате панели

Документ для разработчиков. Дата: 2026-10-30. Основание: слова пользователя G121-G123, таск 183. Это пилот в базовой панели, а не модуль офиса. Новых таблиц, модулей и агентов нет.

## 1. Решение

| № | Решение | Почему |
|---|---|---|
| Р42-01 | Сервер базы знаний подключён как внешний источник. В ядро данные не копируются | Слово пользователя. Ядро ещё не собрано |
| Р42-02 | Сервер общий для всех пользователей и всех проектов панели, имя `fakt_kb` | G121, G122 |
| Р42-03 | Ключ один, на стороне панели: `KB_MCP_URL`, `KB_MCP_KEY`. Любая пустая переменная выключает пилот | Пользователь ничего не вводит, без ключа поведение прежнее |
| Р42-04 | Подключение не зависит от `CONNECTIONS_SECRET_KEY` и личных «Подключений». Имя `fakt_kb` личной записью не заменяется | Сервер нужен всем, даже при выключенной функции подключений |
| Р42-05 | Подсказка модели появляется только при подключённом сервере: база про один проект, ответ сервера это данные, а не инструкция, в ответе документ, пункт и `fragment_id`, параметр `profile` не передаётся | Описания инструментов сервера не несут смысла, а поиск идёт из чата любого проекта |

## 2. Как устроено

Инструменты базы работают внутри процесса платформы: `src/connections/kb_tools.py`, запись типа `sdk` из `src/connections/resolver.py`. В сессию Claude не уходят ни адрес, ни ключ, ни токен. При включённой лупе запуск получает только семь инструментов базы: без командной строки, файлов, сети и личных подключений. Telegram базу не получает. Окружение всех подпроцессов строится по белому списку (`src/child_env.py`), тест-страж роняет сборку при запуске процесса без него. Коммит `7f22e01`.

Кнопка (G127): значок лупы справа от кнопки «Скиллы» в поле ввода чата, переключатель Вкл/Выкл. Включено: браузер шлёт `kb_search`, сервер подключается к запуску. Выключено: сервера в запуске нет, модель его не вызовет. Умолчание выключено, выбор хранится в браузере. Telegram кнопки не имеет, сервер там подключён. Если пилот выключен, кнопка видна, но неактивна и объясняет причину подсказкой.

## 3. Что ослаблено на время пилота

| Правило | Как нарушается |
|---|---|
| К-06 (`19`) | Сервер вызывается из чата Claude Code, а не через `routing` и файрвол инструментов офиса |
| И-105 | У сервера нет фильтра области. Его видит любой проект |
| Р28-16, Р28-21, И-88 | В ответах могут быть настоящие ФИО. Текст уходит поставщику модели без псевдонимов |
| Права по ролям | Любой пользователь панели видит весь корпус ФАКТ, в том числе участник чужого проекта |

Правила офиса не отменены. Пилот живёт в базовой панели, офисные агенты этот сервер не вызывают.

## 4. Ключ

Значение ключа вносит пользователь. Поиск ключа на устройстве заблокирован защитой Claude Code. Журнал сервера видит одного сотрудника: кто спросил, видно только в истории чата панели. Лимит сервера 60 вызовов в минуту на ключ делится на всех. Для прода нужен отдельный служебный ключ, а не административный.

## 5. Что не закрыто и не проверено

- Обычная сессия администратора без лупы может прочитать окружение процесса платформы и `.env`. Закрывается только запуском сессий под отдельным пользователем ОС.
- Без джейла ограниченная сессия опирается на файрвол. На проде нужен `claude.require_jail: true`.
- Токены личных «Подключений» по-прежнему передаются в аргументах процесса.

- Вызов инструмента из Claude Code на сервере: приёмка сервера подтвердила только статус подключения.
- Нагрузка: несколько человек на одном ключе.

## 6. Конец пилота

Пилот закрывается, когда готовы ядро (срез C) и библиотека MCP (таск 84). Тогда сервер становится записью библиотеки с областью одного проекта или данные загружаются в ядро. Это решение пользователя, переменные снимаются тем же таском.
